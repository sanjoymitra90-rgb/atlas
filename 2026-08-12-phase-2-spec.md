## 0. What Phase 2 is

Five tasks, ordered so that each is independently shippable and the risky work comes last:

- **A** — Repo hygiene and deployment. Unblocks pushing to GitHub Pages. Do this first.
- **B** — Security and data-integrity fixes.
- **C** — Phase 1 leftovers.
- **D** — Extract the near-pure logic (`pairGapCalls`, `computeCoverage`, financials).
- **E** — Move CDN dependencies to npm and tighten CSP.

**Stop and hand back after each task.** Do not run A through E in one pass. Task A in particular
must be verified working on the live site before anything else lands.

---

## 1. Hard constraints

Carried forward from Phase 1, plus two new ones.

1. **Moves are moves.** Relocating a function changes nothing but its location and the addition of
   `export`. A reviewer must be able to diff old and new bodies and see zero substantive change.
2. **Moves and fixes never share a commit.**
3. **Every bug fix is test-first.** Write the failing test, confirm it fails, then fix.
   *Phase 1 skipped this. It is not optional in Phase 2 — this phase touches security code, and
   "which change introduced this?" must be answerable.*
4. **Commit as you go.** Phase 1 produced zero commits. Each task in this document should produce
   several. A single end-of-phase commit is a failure condition.
5. **Do not change behaviour to make a test pass.**
6. **The build output must remain a single self-contained HTML file** that opens from `file://`.

## 2. Task A — Repo hygiene and deployment

### A0. Secrets hygiene — DO THIS BEFORE ANY COMMIT

`jwt.csv` sits in the project root. It contains 1,353 rows of real UK telephone numbers and signed
JWTs referencing `witness6.provenant.net`. It is untracked but **not ignored**, so any `git add .`
publishes it to a public repository.

Add to `.gitignore` before staging anything:

```
jwt.csv
*.local.csv
index.html.tmp
screenshots/
_v.mjs
```

Then confirm with `git status --short` that no `.csv` outside `fixtures/` is staged, and with
`git log --all --full-history -- jwt.csv` that it has never been committed. If that command
returns anything, **stop and report it** — history rewriting is not a task to improvise.

Delete `index.html.tmp` (zero bytes) and `_v.mjs` (a reviewer's scratch file).

**Decision required — `dist/`:** it is currently neither tracked nor ignored. Under A1 it is built
by CI and published from an artifact, so it should be **ignored**. Add `dist/` to `.gitignore`.

### A1. GitHub Actions workflow

Create `.github/workflows/deploy.yml`. This builds on push, runs the full test suite, and
publishes to Pages **only if everything passes** — so a broken commit leaves the previous site
live rather than taking the tool down.

```yaml
name: Build and deploy

on:
  push:
    branches: [main]
  workflow_dispatch:

permissions:
  contents: read
  pages: write
  id-token: write

concurrency:
  group: pages
  cancel-in-progress: true

jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: 20
          cache: npm
      - run: npm ci
      - run: npx playwright install --with-deps chromium
      - run: npm run test:unit
      - run: npm run build
      - run: npm run test:e2e
      - uses: actions/upload-pages-artifact@v3
        with:
          path: dist

  deploy:
    needs: build
    runs-on: ubuntu-latest
    environment:
      name: github-pages
      url: ${{ steps.deployment.outputs.page_url }}
    steps:
      - id: deployment
        uses: actions/deploy-pages@v4
```

Note the ordering: unit tests, then build, then e2e against the built output. That matches the
`npm test` script from Phase 1.

### A2. Repository setting

In **Settings → Pages → Build and deployment**, set **Source** to **GitHub Actions** (currently it
will be "Deploy from a branch"). This is a one-time change made in the GitHub web interface.

Include this step in `DEPLOY.md` with the exact menu path, because Sanjoy will be the one clicking
it and he is not a developer.

### A3. `DEPLOY.md`

Write it at the repository root, **addressed to a non-technical maintainer**. No jargon without a
plain-English gloss. It must cover:

1. **What happens when I push a change** — three sentences, no more.
2. **How do I know it worked** — where the green tick appears, roughly how long it takes.
3. **What if it fails** — that the old site stays live, where the failure email goes, and where to
   click to read the error.
4. **How do I undo a bad change** — the exact steps to revert to the previous commit.
5. **Emergency escape hatch** — if the build tooling ever becomes unworkable: take the last good
   `dist/index.html`, place it at the repository root, delete `.github/workflows/deploy.yml`, and
   set Pages back to "Deploy from a branch". This returns the project to its pre-Phase-1 setup.
   Say plainly that nothing about this migration is one-way.
6. **Where the app is hosted** — the live URL.

### A4. Branch protection for this phase

Phase 1 currently sits uncommitted on `main`, and the root `index.html` no longer runs standalone.
Do not push it to `main` until A1 and A2 are in place and verified. If work has already been
pushed to `main`, say so and stop.

### A5. Done when

- `.gitignore` covers everything in A0 and `git status` is clean of stray files
- A push triggers the workflow, tests run, and the live Pages URL serves the built app
- A deliberately broken commit (e.g. a failing unit test on a scratch branch) does **not** deploy
- `DEPLOY.md` exists and a non-developer could follow it

## 3. Task B — Security and data integrity

Each item is its own commit with a test written first.

### B1. Unescaped timestamp cell — live XSS

**Where:** `renderGapTable()`, both the grouped and flat branches.

The Time cell interpolates `row.time` **unescaped** when `timeValid === true`; the invalid branch
escapes it. Every other cell in the row is escaped.

This is reachable. V8's date parser ignores parenthesised comments, so a CSV cell containing
`Jan 1 2025 (<img src=x onerror=alert(1)>)` parses to a valid date, sets `timeValid: true`, and
lands raw in `innerHTML`. Verified against the current implementation.

**Fix:** escape `row.time` in both branches, both paths.

**Test:** Playwright. Add a fixture row containing that payload, upload it, and assert the rendered
cell contains no element node — e.g. that the `<td>` has zero element children and its text
content includes the literal `<img`.

### B2. Unescaped scenario name

**Where:** `renderScenarioList()`.

`s.name` is user-typed, stored in `localStorage`, and interpolated raw into `innerHTML`.
`showToast` also concatenates it, but that path uses `textContent` and is safe.

**Fix:** wrap in `escapeHtml()` — now importable from `src/core/format.js`.

### B3. CSV export headers bypass the injection guard

**Where:** `exportGapData()`.

Data rows go through `csvCell()`. The header row does not — `allHeaders.join(',')`. Custom column
display names are user-supplied, so a name containing a comma silently corrupts column alignment
for every row beneath it, and a name beginning with `=` is unguarded.

**Fix:** `allHeaders.map(csvCell).join(',')`. Apply the same treatment to the header row in the
pair-summary export branch for consistency, even though those headers are fixed strings.

**Test:** unit test on the header-building logic if you extract it; otherwise Playwright, adding a
custom column named `a,b` and asserting the exported header row has the expected column count.

### B4. Imported session data is unvalidated beyond indices

**Where:** `handleImport()`.

Phase 1 fixed the index bounds check. Still unvalidated: `customers[].name` (interpolated into
`innerHTML` downstream), `customers[].lat` / `.lng` (`renderCustList` calls `c.lat.toFixed(2)`,
which throws on a non-number and blanks the endpoint list), `customers[].tier`, and `cellCosts`
values (non-numeric costs propagate `NaN` into the OPEX figure).

**Fix:** validate on import. Drop endpoints whose `lat`/`lng` are not finite numbers, coerce
`tier` to 1–4 or drop it, discard non-numeric `cellCosts` entries, and fold the counts into the
existing "dropped" toast.

### B5. Blob URLs are never revoked

**Where:** `exportGapData()` (two paths), `exportShareReport()`, `exportSessionJSON()`,
`exportOnboardingJSON()`, `exportOnboardingCSV()`. Three `createObjectURL` calls against one
`revokeObjectURL`.

**Fix:** revoke after the click in every export path. Extract a small
`downloadBlob(blob, filename)` helper into `src/core/download.js` and use it everywhere — the
duplication is the reason this was missed.

### B6. Retired metric still present in export

**Where:** `exportGapData()` summary block.

The summary still emits a `Gap` column computed as `Math.abs(signing - verify)`. Both Gap tiles
were deliberately removed from the UI in Phase 11. Exporting a metric the product retired is a
correctness problem, not a cosmetic one — it uses the opposite sign convention to what the UI used
to show.

**Fix:** remove the `Gap` column from the header and the value row. Remove the corresponding
sentence from `docs/SPEC.md` §7.6 in the same commit.

## 4. Task C — Phase 1 leftovers

Small, low-risk. Group them into one or two commits.

- **C1.** The duplicate-endpoint toast reads "Endpoint already added — same location exists". It
  must name the existing entry and its source, because the user is looking at a list where the
  duplicate is not visibly present: `"Kuala Lumpur is already added as an AWS region — same
  physical location"`. Handle both directions (region-then-city and city-then-region).
- **C2.** Two places fire `showToast` twice in succession — `handleImport` (dropped cells and
  dropped endpoints) and `updateOnboardingFinancials` (margin clamp and contingency clamp). The
  toast is a singleton with a 3-second timer, so only the second message is ever seen. Combine each
  pair into one message.
- **C3.** In `e2e/optimizer/opt-review.spec.cjs`, the R13 test declares `toastPromise` and never
  awaits or asserts it. Either assert the toast text or delete the dead lines. The footprint
  assertions in that test are sound and should stay.
- **C4.** `validateUKNumber` reports `"Non-UK destination (+331)"` for `+33123456789`. The country
  code regex takes up to three digits greedily. Match against a list of known country-code prefixes
  (longest match wins), or if that is too broad a change, cap the display at two digits and note
  the limitation. This is cosmetic but it appears in a user-facing chip.
- **C5.** The physics test returns `{ error, violations: [] }` when `window._matrix` is missing,
  and the assertion `expect(violations).toEqual([])` would pass on that path. Assert
  `result.error` is undefined as well, so removing the bridge cannot silently disable the check.

## 5. Task D — Extract the near-pure logic

Phase 1 extracted functions that were *already* pure. These three are not, and converting them is
a refactor rather than a move. **Characterisation tests come first.**

The procedure for each, in order:

1. Write Playwright tests that capture current behaviour against the existing fixtures. Record the
   actual numbers the app produces today. Do not consult `docs/SPEC.md` for expected values.
2. Change the function's signature to take everything it needs as arguments and return a result
   instead of mutating globals.
3. Move it to `src/`.
4. Update the call site to pass state in and assign the result out.
5. Confirm the characterisation tests still pass, unchanged.

### D1. `pairGapCalls()` → `src/auditor/pairing.js`

Currently mutates `gapData` rows in place and writes `gapPairSummary`. Reads `gapPairingKeys`,
`gapColumnMapping`, `gapPairWindow`.

Target signature:

```js
export function pairCalls(rows, { pairingKeys, columnMapping, pairWindow })
// returns { rows, summary } — rows being new objects, not mutated inputs
```

**While you are in here — required, not optional:** the pairing-key expression is duplicated
**four times** inside this one function, in two slightly different forms. Extract
`function pairKey(row, pairingKeys, columnMapping)` and use it at all four sites. This duplication
has already caused shipped bugs twice in this project's history.

**Do not** attempt to fix the O(n²) duplicate-reclassification loop in this phase. Note it in the
commit message and leave it.

### D2. `computeCoverage()` and `computeGreenPlan()` → `src/optimizer/coverage.js`

`docs/SPEC.md` invariant 6 claimed these were pure; Phase 1 corrected the wording to "DOM-free".
They read the module-level `regions` binding and call `estimateRegionCost()`, which reads
`cellCosts`, `baselineMode` and `specificBaselineIdx`.

Make `regions` and a `getRegionCost` function part of the `input` object. Once done, invariant 6
becomes true and should be restored to its original wording in `docs/SPEC.md`.

**Known bug to fix while here, with a test:** the memoisation key is
`` `${cellIdx}|${cust.idx ?? cust.name}` ``. Raw customer objects have no `idx` — it is assigned
only after classification — so the same endpoint is cached under two different keys in the two
loops, and two endpoints sharing a name collide. The name-collision path is reachable via session
import, which performs no name de-duplication. Assign a stable `idx` to every customer before the
first loop and key on it alone.

### D3. Onboarding financial maths → `src/onboarding/financials.js`

Extract the arithmetic only — hours, contingency, internal cost, customer price, clamping — as a
pure function taking `{ totalHours, rate, marginPct, contingencyPct }`. Leave DOM reads and writes
in `updateOnboardingFinancials()`, which calls it.

This makes the margin and contingency clamping unit-testable rather than only reachable through a
browser.

## 6. Task E — Dependencies to npm, and CSP

**The riskiest task in this phase. Do it last, and only after A–D are committed and green.**

### E1. Move four libraries from CDN to npm

`leaflet`, `chart.js`, `html2pdf.js`, `dhtmlx-gantt`. Install, import in the relevant module, and
delete the corresponding `<script>` and `<link>` tags.

This retires an entire class of failure that has hit this project three times: recalled SRI hashes,
a moving `edge` version tag, and a silently absent Chart.js.

### E2. Tailwind from CDN runtime to build-time — HIGH RISK

`cdn.tailwindcss.com` generates classes at runtime by evaluating JavaScript, which is why the CSP
requires `unsafe-eval`. Moving to build-time Tailwind removes that requirement.

**The risk:** build-time Tailwind removes any class it does not find in your source. The app builds
class strings inside JavaScript template literals in at least 16 places, and at least one is
constructed dynamically — `text-${confColor}` in the confidence chip. That class will be purged and
the chip will lose its colour.

**Required procedure:**

1. Configure `content` to scan `index.html` and `src/**/*.js`.
2. Grep for every dynamically constructed class name — start with `text-${`, `bg-${`, `border-${`
   — and add each possible resolved value to the Tailwind `safelist`. Do not guess; enumerate the
   values the code can actually produce.
3. **Visual verification is mandatory.** `e2e/screenshot.js` already produces ten screenshots
   covering the gateway, upload prompt, dashboard, charts, table, both modals, grouped view and
   pair panel. Capture the full set **before** this change, capture again **after**, and compare
   each pair. Any difference is a purged class until proven otherwise.
4. If the comparison shows differences you cannot resolve within a reasonable effort, **revert E2
   and report**. Keeping the Tailwind CDN is an acceptable outcome; shipping a silently
   restyled app is not.

### E3. Tighten CSP

Once E1 and E2 are done, `unsafe-eval` can go. Replace the meta tag with:

```
default-src 'self'; script-src 'self' 'unsafe-inline'; style-src 'self' 'unsafe-inline';
img-src 'self' data: https:; font-src 'self' data: https:; connect-src 'none';
```

`unsafe-inline` must stay for now — the app has 197 inline event handlers. Removing it requires
converting them to delegated listeners, which is deferred (§7).

**Correct the privacy claim while here.** `docs/SPEC.md` states that `connect-src 'none'`
"enforces the privacy claim at browser level". That is overstated: `img-src https:` still permits
exfiltration via image beacons. Reword to describe what is actually enforced.

### E4. Font Awesome

Ten `aria-label`s and roughly 200 icon references depend on it. Moving it to npm means bundling
font files, which conflicts with single-file output. **Leave Font Awesome on its CDN** and note it
as the one remaining external dependency. Revisit only if offline capability becomes a requirement.
