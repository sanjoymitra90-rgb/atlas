# ATLAS — Phase 1 Implementation Spec

**For:** the AI coding agent implementing this phase.
**From:** review pass, 2026-08-12.
**Status of this document:** authoritative for Phase 1 scope. If something here contradicts
`docs/SPEC.md`, this document wins *for the duration of this phase only* — several `docs/SPEC.md`
statements are known-stale and are corrected in Phase 6, not here.

**No line numbers anywhere in this document.** Anchor on function names, file paths, element IDs
and `data-testid` values.

---

## 0. What Phase 1 is, in one paragraph

ATLAS is a 6,555-line single-file app. Its Playwright suite reports 182 passing tests, but six of
the tests that guard the most important bug fixes do not test the application — they re-implement
the logic inside `page.evaluate()` and assert against their own copy. Phase 1 replaces that
arrangement with real unit tests by extracting the app's pure logic into importable modules, and
then fixes four correctness bugs that the fake tests were pretending to cover.

**Phase 1 changes no user-visible behaviour except the four bug fixes in §5.**

---

## 1. Hard constraints

These are not preferences. Violating any of them means the phase has to be redone.

1. **Moves are moves.** When relocating a function, change nothing but its location and the
   addition of `export`. No renaming, no reformatting, no "while I'm here" fixes, no comment
   edits. A reviewer must be able to diff the old and new function bodies and see zero
   substantive change.
2. **Moves and fixes never share a commit.** Every bug fix is its own commit, landing *after* the
   move that made it testable.
3. **Every bug fix is test-first.** Write the failing test, show it failing, then fix. A fix
   committed without a test that fails before it is not done.
4. **Do not change behaviour to make a test pass.** If a test disagrees with the app, work out
   which is right and say so. Two of the existing tests encode buggy behaviour (see §6).
5. **The build output must remain a single self-contained HTML file** that opens from `file://`
   with no server. This is a distribution requirement, not a preference.
6. **Do not touch:** the Optimizer's UI, the Onboarding Gantt, chart rendering, the table
   renderer, or anything in `docs/`. Those are Phases 2–6.

### A4. `package.json` scripts

```json

"test:unit": "vitest run",
"test:e2e": "playwright test",
"test": "npm run test:unit && npm run build && npm run test:e2e"
```

### A5. Playwright must now target the build output

`e2e/**` currently loads `pathToFileURL(.../index.html)`. After the split, the dev `index.html`
uses `<script type="module">`, which browsers refuse to load over `file://`. Update the shared
path resolution — `e2e/gap/helpers.js` (`APP_URL`), `e2e/global-setup.js` (`APP`), and the
per-spec `APP` constants in `e2e/optimizer/*` and `e2e/onboarding/*` — to point at
`dist/index.html`, and make `npm test` build before running e2e (already handled by A4).

Prefer extracting a single `e2e/app-url.js` that all specs import, so this path is defined once.

### A6. Known wrinkles — expect these, do not be surprised

- **Font Awesome** ships web fonts. `viteSingleFile` cannot inline external font files pulled from
  a CDN stylesheet. For Phase 1, leave the Font Awesome `<link>` as a CDN reference. Migrating
  icons is a Phase 2 concern.
- **DHTMLX Gantt, Leaflet, Chart.js, html2pdf** stay as CDN `<script>` tags in Phase 1. Moving
  them to npm is Phase 2. Do not attempt it here.
- Because of the two points above, the Phase 1 build output is single-file but **not yet
  offline-capable**. That is expected and is resolved in Phase 2.

### A7. Done when

- `npm run dev` serves a working app at localhost with all three modules functional
- `npm run build` produces `dist/index.html` that opens from disk and works
- `npm test` runs unit tests, builds, then runs all 182 Playwright tests — all green

## 4. Task C — Unit-test the extracted functions

Create `src/auditor/validate.test.js`, `src/auditor/parse.test.js`, `src/auditor/buckets.test.js`.

These are the first real tests in the project. Write them against **observed current behaviour**,
not against `docs/SPEC.md` — the docs contain known-stale claims.

Pattern:

```js
import { describe, it, expect } from 'vitest';
import { normalizePhoneNumber, validateUKNumber } from './validate.js';

describe('validateUKNumber', () => {
  it('accepts a well-formed UK mobile', () => {
    expect(validateUKNumber('+447305409280').category).toBe('valid');
  });
  it('categorises a non-UK country code separately from malformed', () => {
    expect(validateUKNumber('+33123456789').category).toBe('non-uk');
  });
});
```

Minimum coverage required before this task is complete:

- **`validateUKNumber`** — one case per returned `category` (`valid`, `malformed`, `non-uk`,
  `suspected-test`), plus each `reason` string, plus empty input.
- **`normalizePhoneNumber`** — see §5.1; the bug cases become the tests.
- **`gapReasonBucket`** — one case per bucket it can return. Note that it can return `'truncated'`
  but no caller ever produces a reason containing "truncated". Assert the current behaviour and
  leave a `// TODO(phase-3)` comment; do not fix it here.
- **`parseGapCSV`** — quoted commas, quoted newlines, CRLF, BOM, `""` escapes, empty rows, short
  rows, and the duplicate-header case from §5.2.
- **`getAutoBucketInterval`** — the four documented boundaries (≤1 h, ≤6 h, ≤3 d, >3 d).

## 5. Task D — The four bug fixes

Each is a separate commit. Each begins with a failing test.

### 5.1 `normalizePhoneNumber` precision guard is bypassed

**Where:** `src/auditor/validate.js`, `normalizePhoneNumber`.

The scientific-notation guard uses a regex requiring exactly one digit before the decimal point
and no leading sign. Several real-world shapes bypass it and are then reported **Valid** despite
having lost digits. Verified against the current implementation:

| Input | Current result | Correct result |
|---|---|---|
| `4.47305E+11` | rejected | rejected ✓ |
| `44.7305E+10` | `+447305000000` → **Valid** | rejected |
| `4473054E+5` | `+447305400000` → **Valid** | rejected |
| `+4.47305E+11` | `+447305000000` → **Valid** | rejected |

**Fix:** generalise the guard to any `<digits>[.<digits>]E+<digits>` form, with an optional
leading `+`. Compare total significant digits in the mantissa against the implied digit count from
the exponent; if the mantissa carries fewer, the value lost precision — return the original string
unchanged so it fails validation downstream.

**Do not** attempt to add a `truncated` category in this phase. `gapReasonBucket` and
`ukPillHtml` already have dead branches for it; wiring them up is a Phase 3 product change.

**Tests:** all four rows of the table above, plus a non-scientific control (`447305409280`
→ `+447305409280` → valid).

### 5.2 Duplicate CSV headers still collide when there are three or more

**Where:** `src/auditor/parse.js` if the de-dup lives there after extraction; otherwise
`readGapFile` in the main file. Move the de-dup logic into `parse.js` as part of this fix so it is
unit-testable — this is the one place a small behaviour-preserving move is allowed inside a fix
commit, because the logic is currently untestable where it sits.

The counter is assigned but never incremented, so `['A','A','A']` produces `['A','A (2)','A (2)']`
— the collision returns and one column silently overwrites the other in the row object.

**Fix:** increment the counter per occurrence, producing `['A','A (2)','A (3)']`.

Additionally, `window._dupedHeaders` is set but never surfaced anywhere. Append the count to the
post-analysis toast, e.g. `· 2 duplicate column name(s) renamed`.

**Tests:** two duplicates, three duplicates, duplicates of two different names, an empty header
name, and a header name that collides with a generated suffix (`['A','A','A (2)']`).

### 5.3 Footprint cells are dropped silently on session import

**Where:** `handleImport` in the main file (Optimizer IO — not yet extracted; fix in place).

`droppedCells` is computed and then never read. Out-of-range **endpoint** indices produce a toast;
out-of-range **footprint** indices are discarded in silence. This is the exact silent-wrong-plan
outcome the import guard exists to prevent.

**Fix:** emit an error toast when `droppedCells > 0`, matching the wording of the existing endpoint
toast: `` `${droppedCells} cell(s) dropped — unknown region index` ``. If both counts are non-zero,
show a single combined toast rather than two competing ones (the toast element is a singleton with
a 3s timer; two calls means the user only ever sees the second).

**Test:** Playwright, not unit — this is DOM-coupled. Replace the existing
`R13 — import with out-of-range region index drops it` test in `e2e/optimizer/opt-review.spec.js`,
which currently re-implements the filter inline and asserts against its own result. The
replacement must drive the real file input with a crafted session JSON containing an
out-of-range `selectedFootprint` entry, and assert the toast text.

### 5.4 Margin clamping is invisible and one-directional

**Where:** `updateOnboardingFinancials` in the main file (fix in place; extraction of the
financial maths is Phase 2).

Two problems:

- **Upper bound:** when margin ≥ 100 the variable is clamped to 99 but `#ob-margin` still displays
  the value the user typed. The user reads 100%, the quote is computed at 99%. The toast also
  re-fires on every keystroke while the field reads `100`.
- **Lower bound:** negative margin is entirely unguarded. `-50` yields a multiplier of 1.5 and
  quotes **below internal cost**.

**Fix:** clamp to the range 0–99 inclusive, write the clamped value back into `#ob-margin` so the
control and the maths agree, and fire the toast only when the clamp actually changes the value
(compare pre- and post-clamp).

Apply the same lower-bound guard to `#ob-contingency` — negative contingency currently reduces
billable hours below base hours.

**Test:** extend `e2e/onboarding/onb-smoke.spec.js`. Assert that after typing `100` the input
*reads* `99`, and that after typing `-50` the customer price is greater than or equal to internal
cost.

### 5.5 Endpoint double-counting — REQUIRES SIGN-OFF BEFORE IMPLEMENTING

**Where:** `tryAddEndpoint` in the main file.

26 of the 32 AWS regions share an exact name *and identical coordinates* with a `worldCities`
entry. The dedup identity is `r{regionIdx}` for regions and `c{name}` for cities — different keys —
so the same physical location can be added twice.

Before the latency model was unified this was a meaningful distinction: the two paths produced
different estimates. They now produce identical estimates, so the second entry is pure
double-counting — it inflates the endpoint total, inflates coverage counts, and skews greedy
selection, because a candidate cell covering a duplicated location outranks one covering a genuine
second city.

**`docs/FEATURES.md` currently documents the duplicate-add as intended behaviour** ("The same
physical location can be added two ways… and the tool will estimate different latencies for
each"). That sentence is now false regardless of what is decided here.

**Do not implement this fix until Sanjoy confirms the intended behaviour.** Ask; do not choose.
The recommended fix, if approved: derive the dedup key from resolved location (latitude and
longitude rounded to ~3 decimal places) rather than from the source tab, reject the duplicate with
the existing toast, and update the `docs/FEATURES.md` paragraph in the same commit.

## 6. Task E — Retire the fake tests

Once §4 exists, the Playwright tests that pretend to cover the same ground must go or be repaired.
Leaving them is worse than deleting them: they report coverage that does not exist.

In `e2e/gap/gap-review.spec.js`:

- **`R9 — truncated scientific notation fails validation`** — delete. Superseded by §5.1 unit
  tests. It re-implements the regex inside `page.evaluate` and never calls the app.
- **`R16 — csvCell guards formula injection`** — delete. Same pattern; superseded by a unit test
  on `csvCell` in `src/core/format.test.js`, which you should add as part of §4.
- **`R15 — escapeHtml prevents HTML injection`** — keep, but it currently only exercises the
  helper. Add a second assertion that uploads a fixture containing markup in a customer field and
  asserts the rendered cell contains no live element.
- **`R8 — charts update when filter is applied`** — strengthen. It currently asserts only that a
  canvas element exists, which would pass if chart rendering were deleted entirely. Assert instead
  that the chart's dataset length or point count changes after a filter is applied.
- **`R3/R27 — Chart.js is defined`** — keep as-is. It is a genuine check.

In `e2e/optimizer/opt-review.spec.js`:

- **`R5 — physics invariant`** — **rewrite; it currently asserts nothing.** The body builds a loop
  that computes the light-in-fibre floor, discards the result, then asserts `regionCount > 0` and
  that two regions are not co-located. It would pass if every matrix entry were zero.
  The replacement must iterate all 32×32 pairs, compare `matrix[i][j]` against
  `haversine(regions[i], regions[j]) * 0.01`, collect every violation, and assert the list is
  empty. **This currently passes on real data — I verified zero violations — so the rewrite locks
  in a property you already have.** `window._regions` is available; expose the matrix on `window`
  if it is not already.
- **`R13 — import with out-of-range region index`** — rewrite per §5.3.
- **`R4 — ap-southeast-5 is Kuala Lumpur`** — keep. This is a good test.

## 9. Notes for the implementing agent

- **`docs/SPEC.md` is stale in six places.** It carries "known defect" markers referencing
  `REVIEW.md`, a file deleted in Phase 9. Every one of those markers describes a bug that has since
  been fixed. It also states 5,984 lines (actual: 6,555) and 761 triangle-inequality violations
  (actual: 856). Treat the code as the source of truth; the doc is corrected in Phase 6.
- **Invariant 6 in `docs/SPEC.md` is false.** It claims `computeCoverage()` and `computeGreenPlan()`
  are pure. They read the module-level `regions` binding and call `estimateRegionCost()`, which
  reads `cellCosts`, `baselineMode` and `specificBaselineIdx`. They are DOM-free, not pure. Do not
  attempt to extract them in Phase 1 — converting them to genuinely pure functions requires a
  signature change and characterisation tests, which is Phase 2 work.
- **`pairGapCalls()` is also not pure** — it mutates `gapData` in place and writes `gapPairSummary`.
  Same reasoning: leave it for Phase 2.
- If any statement in this document turns out to be wrong when checked against the code, **say so
  and stop** rather than working around it. A wrong premise silently built upon is the failure mode
  this project has hit repeatedly.
